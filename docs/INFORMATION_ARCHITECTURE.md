# 信息架构（Information Architecture）

本文件定义 App 的导航结构、页面清单与路由规划，回答"用户去哪里""从哪进""到哪出"，不定义数据实现方式。

相关文档：[产品需求](./PRODUCT_REQUIREMENTS.md) · [项目简介](./PROJECT_BRIEF.md) · [架构](./ARCHITECTURE.md) · [决策记录](./DECISIONS.md) · [路线图](./ROADMAP.md)

> 第 4 节的目录规划随功能开发逐步落地，标注「后续规划」的路由尚未创建。
>
> 第 6 节是变美记录与套餐资产（schema v4）的**目标信息架构，全部规划中、尚未实现**（例外是第 6.6 节：日期选择器已由 BT-0019A 落地；省市选择器组件已由 BT-0019B1 实现，但尚未接入任何页面；项目两级目录数据已由 BT-0021A 实现，但还没有选择器），不改变第 2 至 5 节的现状。

## 1 一级导航

App 使用五个一级 Tab，顺序固定：

| 序号 | Tab | 主要任务 | 承载的核心场景 |
| --- | --- | --- | --- |
| 1 | 首页 | 看概览、提醒与快捷操作 | S3 查看余次和有效期、S4 回顾 |
| 2 | 记录 | 管理套餐与核销历史 | S1 购买后录入、S2 完成后核销 |
| 3 | 百科 | 搜索与了解医美知识 | S5 查询项目、仪器、材料知识 |
| 4 | 心愿单 | 管理想做的项目与收藏 | S6 收藏和记录想做项目 |
| 5 | 我的 | 管理账号与数据 | S7 换机与恢复 |

导航原则：

- 页面详情使用**栈式导航**进入，每个 Tab 拥有独立导航栈。
- 新增与编辑以**独立全屏页面**为主，覆盖 Tab 栏，避免误触丢失填写内容。
- 仅将日期选择、二次确认、单条核销等轻量交互作为**弹层**。
- 任何页面都必须有明确的返回路径，不存在死链。

## 3 页面清单

字段说明：**阶段**列中"是"表示属于第一阶段（R0 静态原型 + R1 本地闭环）需要落地的路由；"静态占位"表示第一阶段只建路由与静态页面，不实现业务逻辑。

### 3.1 首页 Tab

#### 3.1.1 首页总览

| 项 | 内容 |
| --- | --- |
| 目的 | 让用户在打开 App 的三秒内知道"还有什么没用完""接下来要做什么" |
| 入口 | App 启动默认页；任意 Tab 点击"首页" |
| 出口 | 新增购买记录、快速核销、临期提醒、记录列表（带筛选）、核销历史、消费统计、百科首页、心愿单列表 |
| 关键操作 | 新增购买记录；快速核销；查看临期提醒区（最多 3 个套餐）并点击「查看全部」进入完整提醒页；点击提醒卡片进入套餐详情；点击待核销/临期数字跳转到对应筛选结果；查看最近一次核销 |
| 数据依赖 | 待核销项目数、剩余总次数、临期与已过期套餐（含剩余次数与有效期）、最近三条核销 |
| 空状态 | 引导添加第一条购买记录，并说明录入后可管理剩余次数；不显示 0 值卡片堆叠 |
| 错误状态 | 优先展示本地缓存并标注"可能不是最新"，提供重试；无缓存时展示错误说明与重试按钮 |
| 阶段 | 是 |

#### 3.1.2 临期提醒

| 项 | 内容 |
| --- | --- |
| 目的 | 集中查看有效期在 30 天内、以及已过期但仍有剩余次数的套餐 |
| 入口 | 首页临期提醒区的"查看全部"（常驻，条数不足 3 条时同样存在） |
| 出口 | 购买记录详情；返回首页 |
| 路由 | `/(tabs)/home/expiring`，压在首页 Tab 自己的栈内，保留 Tab 栏 |
| 关键操作 | 浏览"已过期"与"30天内到期"两个区块；点击任意一条进入其所属套餐详情 |
| 数据依赖 | 当前档案下填写了有效期的套餐、各项目购买次数与有效核销数（用于派生套餐剩余次数）、机构与城市快照 |
| 展示规则 | 已过期区块在前，按有效期倒序；30天内区块（含今天到期）在后，按有效期升序；相同日期按购买日期倒序再按记录标识升序。每条同时显示到期状态文案与明确日期（如"已过期8天 · 2026-09-10"），以及"剩余 N 次"。机构为空时显示"未填写机构"，城市为空时整段省略 |
| 空状态 | 提示"暂无临期套餐"并说明未来 30 天没有需要提醒且仍有剩余次数的套餐，不提供无意义的禁用按钮 |
| 错误状态 | 展示"没能读取临期提醒"与重试入口；后台刷新失败保留已有内容并标明可能不是最新，不暴露技术细节 |
| 阶段 | 是 |
| 约束 | 本页**只读**：不提供核销、编辑有效期、删除套餐的入口。**已过期不禁用任何东西**——剩余次数不因过期归零，其项目在快捷核销中仍可选择并完成核销（[ADR-017](./DECISIONS.md#adr-017-套餐过期后仍允许核销但保存前必须明确提醒)、PRD-RED-014）。状态不得只靠颜色表达，已过期与即将到期都必须带文字（PRD-NFR-005）。文案只陈述日期事实，不出现"建议复购""该做第二次了"等表述（PRD-NFR-002）。提醒窗口第一版固定 30 个自然日，不提供设置项（PRD 第 8.4 节） |

#### 3.1.3 消费统计

| 项 | 内容 |
| --- | --- |
| 目的 | 按购买与核销两种口径回顾消费分布 |
| 入口 | 首页"消费概览"入口 |
| 出口 | 返回首页；从某一维度下钻到记录列表（带筛选） |
| 关键操作 | 切换统计口径（按购买 / 按核销）；切换年份与月份；按分类、项目、机构查看分布 |
| 数据依赖 | 购买记录、有效核销记录、项目分摊单价 |
| 空状态 | 无记录时引导录入；所选区间无数据时提示"该区间没有记录"，不回退全量 |
| 错误状态 | 展示失败说明与重试，不展示不完整的图表 |
| 阶段 | 否（R4） |

### 3.2 记录 Tab

#### 3.2.1 记录列表

| 项 | 内容 |
| --- | --- |
| 目的 | 集中管理全部套餐，快速定位"还没做完的" |
| 入口 | 记录 Tab；首页各统计数字跳转（携带预设筛选） |
| 出口 | 购买记录详情、新增购买记录、快速核销、核销历史 |
| 关键操作 | 切换套餐视图 / 项目余次视图；筛选（全部、待核销、已用完、临期、已过期）；按套餐名、项目名、机构名搜索；按分类、机构、城市筛选；清除筛选 |
| 数据依赖 | 购买记录、套餐项目、各项目派生剩余次数、有效期 |
| 空状态 | 区分"从未录入"（引导新增）与"当前筛选无结果"（提供清除筛选入口） |
| 错误状态 | 展示错误说明与重试；已缓存列表继续可见可滚动 |
| 阶段 | 是 |

#### 3.2.2 购买记录详情

| 项 | 内容 |
| --- | --- |
| 目的 | 查看单个套餐的完整信息与使用情况 |
| 入口 | 记录列表；首页最近记录；心愿单完成后创建的记录 |
| 出口 | 编辑购买记录、快速核销、百科详情（项目关联条目时）、返回列表 |
| 关键操作 | 编辑套餐；对有余次的项目发起核销；查看与**撤销**单条核销；删除套餐（二次确认） |
| 数据依赖 | 套餐基础信息、项目列表及派生次数、该套餐全部核销记录 |
| 空状态 | 尚无核销记录时提示"还没有核销记录"，并给出核销入口 |
| 错误状态 | 加载失败展示重试；删除或撤销失败保留原状态并说明原因，不假装成功 |
| 阶段 | 是 |
| 约束 | 删除套餐的二次确认弹层必须同时显示**受影响的项目数量**、**受影响的核销记录数量**与**"删除后不可恢复"**；确认后永久删除，项目与核销记录一并消失（[ADR-016](./DECISIONS.md#adr-016-套餐永久删除核销记录使用作废机制)、PRD-PUR-009、PRD-PUR-012）。**不存在回收站页面，也不存在任何恢复入口**；被删套餐关联的机构不随之删除。单条核销只提供"撤销核销"，不得呈现为删除记录（PRD-RED-011） |

#### 3.2.3 核销历史

| 项 | 内容 |
| --- | --- |
| 目的 | 以时间维度集中回顾所有套餐、所有项目的每一次核销 |
| 入口 | 记录列表的次要入口"查看全部核销记录"；首页"最近记录"（后续接入） |
| 出口 | 购买记录详情；快速核销（全部为空时的引导）；返回 |
| 路由 | `/(tabs)/records/history`，压在记录 Tab 自己的栈内，保留 Tab 栏 |
| 关键操作 | 按"全部 / 有效 / 已撤销"切换状态筛选（默认全部）；按核销日期倒序浏览；查看当前筛选的条数；点击任意一条进入其所属套餐详情 |
| 数据依赖 | 当前档案下的全部核销记录（含**已撤销**、已用完与已过期套餐下的记录）、所属项目与套餐名称、核销自身的机构与城市快照 |
| 展示规则 | 按核销日期所在的**自然月份**分组（如"2026年9月"），分组只用于展示，不改变业务日期；机构为空时显示"未填写机构"，城市、备注、撤销原因为空时整段省略 |
| 空状态 | 全部为空时提示"还没有核销记录"并给出"记录一次"入口；"有效"与"已撤销"筛选无结果时分别提示没有该类记录 |
| 错误状态 | 展示"没能读取核销历史"与重试入口，不暴露技术细节 |
| 阶段 | 是 |
| 约束 | 本页**只读**：不提供编辑、删除、撤销或恢复核销的操作，撤销仍只在购买记录详情内进行（PRD-RED-011）。已撤销的记录**保留展示**并明确标注，不得当成已删除隐藏，也不计入有效次数。机构与城市一律取核销记录自身的快照，不得替换为套餐当前的机构或城市（PRD-INST-005、PRD-PUR-018）。按分类、项目、机构筛选与间隔天数统计为后续增强；一旦提供，间隔天数**只作事实展示**，不出现"正常""过快""建议复购"等评价或推销表述（PRD-NFR-003） |

### 3.3 百科 Tab

#### 3.3.1 百科首页

| 项 | 内容 |
| --- | --- |
| 目的 | 提供内容入口，承接高频知识浏览 |
| 入口 | 百科 Tab；首页轻量回访入口 |
| 出口 | 百科详情 |
| 路由 | `/(tabs)/catalog` |
| 关键操作 | 在搜索框内输入关键词；在「全部」与四个浏览分类（基础认知、光电项目、注射项目、护理与安全）之间切换；点击文章卡片进入详情 |
| 数据依赖 | 随 App 本地打包的百科文章（标题、摘要、分类、标签、别名），无网络请求 |
| 展示规则 | 搜索框在上、分类 Chip 在下、其后是当前筛选的文章条数与文章列表。搜索范围为标题、摘要、标签与别名；去首尾空格、折叠连续空白、英文大小写不敏感、中文直接包含匹配；多词之间为「与」的关系，允许分别命中不同字段；搜索与分类同时生效。结果保持编辑顺序，**不做相关性评分**。卡片展示标题、摘要、分类与最多 3 个标签，以及「查看详情」，整张可点击 |
| 空状态 | 全库为空时提示「百科内容正在整理中」，不显示假文章；筛选无结果时提示「没有找到相关内容」「试试更换关键词或选择其他分类」并提供「清除筛选」 |
| 错误状态 | 正文随 App 打包，本页没有网络请求，因此没有加载态与失败重试 |
| 阶段 | 是 |
| 约束 | **单轴筛选**，只使用四个浏览分类（PRD 第 10.1.1 节）；PRD 第 10.1.2 节的五类内容类型尚未实现，界面上不出现空 Chip。不得出现个性化推荐、猜你喜欢、按套餐推断、广告与效果排名。不保存搜索历史。列表用 `FlatList`，不用 `ScrollView` 渲染全部 |

| 关键操作 | 输入关键词（需防抖）；按内容类型筛选；选择结果 |
| 数据依赖 | 百科条目的名称与别名索引 |
| 空状态 | 无结果时提示未找到，并提供"使用自定义名称"的出口（从表单进入时） |

| 约束 | 独立路由 `/(tabs)/catalog/search` 与查询参数 `q`、`type`、`pickFor`，以及「从新增套餐表单选择项目后回填」都属于这一页，未来实现时一并落地。**本轮不建立无法使用的空路由** |

#### 3.3.3 百科详情

| 项 | 内容 |
| --- | --- |
| 目的 | 提供单个条目的中立信息 |
| 入口 | 百科首页；心愿单 Tab 的「收藏文章」视图；后续：购买记录详情中的项目名称、心愿详情 |
| 出口 | 返回来源列表（从百科首页进入回百科首页，从收藏文章进入回收藏文章视图）；新增心愿（`/wishlist/new?articleSlug=<slug>`）；后续：相关条目 |
| 路由 | 同一个页面实现由两个薄路由复用：从百科首页进入走 `/(tabs)/catalog/[entryId]`，从收藏文章进入走 `/(tabs)/wishlist/article/[entryId]`。两者都压在**进入它的那个 Tab 自己的栈内**，保留 Tab 栏。`entryId` 传文章的 slug，路由只传标识，不传正文 |
| 关键操作 | 阅读正文；收藏 / 取消收藏；加入心愿单；点击资料来源在系统浏览器中打开；返回。后续：跳转相关条目 |
| 数据依赖 | 该文章的分类、标题、摘要、正文章节、需要知道的限制、什么时候应及时联系专业人员、资料来源、审核状态与内容复核日期；以及当前档案对本文的收藏状态（来自本地数据库） |
| 展示规则 | 顺序固定：返回入口 → 标题与摘要 → 分类标签 → 中立提示条 → **收藏 / 加入心愿单两个次按钮** → 正文章节 → 「需要知道的限制」→「什么时候应及时联系专业人员」→「资料来源」→ 审核状态与「内容复核于 YYYY-MM-DD」。资料来源每条显示机构、来源类型、标题与「在浏览器中打开」 |
| 空状态 | 选填区块为空时整段省略，不显示空标题 |
| 错误状态 | 文章标识无效时显示「找不到这篇内容，它可能已经更新。」并提供返回百科的入口；收藏状态读取或写入失败时给出中文说明并保持原状态，正文不受影响；资料来源无法打开时给出中文提示，页面不崩溃，不显示技术错误 |

| 展示规则 | 标题与一句话说明 → 中性提示条「备份包含个人消费记录和机构信息，请保存到你信任的位置。」→ 备份内容清单（套餐与项目、核销含已撤销、机构含已归档、心愿、百科收藏）→ 一句说明百科正文随 App 打包因此不在备份里 → 主按钮「导出备份」→「从备份恢复」区块：先一句说明「整体替换、备份里没有的会被删除、无法在 App 内撤销，建议先导出一份当前数据」，再是次按钮「选择备份文件」（已选过时改为「换一个备份文件」）。选中并校验通过后，在该按钮之上出现摘要卡片（备份生成时间、备份格式版本、套餐、套餐项目、核销记录、机构、心愿、百科收藏的条数，每行是一个读屏节点），其下才出现危险按钮「恢复这份备份」——**没有摘要时这个按钮不存在** |
| 空状态 | 导出：没有任何记录时导出的是一份合法的空备份，不禁用按钮，也不假装出错。恢复：未选择文件时没有摘要卡片与恢复按钮，不显示空壳占位 |
| 错误状态 | 按失败环节给一句中文说明，按钮恢复可用可重试，数据一行不变：导出（读取失败 / 生成失败 / 设备不支持分享 / 打开分享面板失败）；恢复（打不开文件选择器 / 读不出文件 / 「这个文件不是有效的备份文件。」/「这个备份来自更新版本，当前 App 暂时无法恢复。」/「备份内容不完整或存在关联错误。」/「备份文件过大，无法恢复。」/ 写入失败已整体回滚）。一律不显示 SQL、表名、绝对路径与堆栈 |
| 阶段 | 是 |
| 约束 | 导出是**只读**操作，不修改任何一行数据（PRD-DATA-012）。恢复是**整体覆盖**：备份里没有的记录会被删除，全部写入在一个事务内完成，任何一步失败都逐行回滚，不留半旧半新的库（PRD 第 15.2.6 节、[ADR-019](./DECISIONS.md#adr-019-从备份恢复采用整体覆盖--单事务备份文件一律当作不可信输入)、PRD-DATA-019、PRD-DATA-025）。**校验通过只是展示摘要，绝不代表已经写入**；写入只发生在用户在确认框里点下「确认恢复」之后，弹窗标题为「用这份备份覆盖当前数据？」，两个选项是「返回检查」与「确认恢复」，**不得使用「同步」「导入一些数据」「继续」这类模糊文案**（PRD-DATA-021）。备份文件是**不可信输入**：只读用户主动选中的那一个文件，缓存副本读完即删，10 MiB 以上在解析前就拒绝，文件里的任何 SQL、表名与列名都不执行（PRD 第 15.2.6.2 节）。临时文件只写入 App 缓存目录，导出分享成功、失败或用户取消后都要清理；两者都不上传任何服务器，不申请新权限（PRD-DATA-013、PRD-DATA-015）。**一页只有一个实心主按钮**：导出是主按钮，选文件是次按钮，「恢复这份备份」用危险语义（白底描边，不铺大面积红），并与导出隔开在自己的区块里。进行中的按钮禁用并把状态写进文案（「正在生成备份…」「正在读取备份…」「正在恢复…」），导出与恢复互斥，连点只执行一次；**恢复进行中不提供取消按钮**（PRD-DATA-027）。系统分享面板不会告诉 App 用户最终存到了哪里，所以导出完成提示只能说「备份文件已生成」并请用户确认自己选了保存位置，**不得谎称已保存成功**；恢复成功后给一条克制提示并回到首页，各页面在获得焦点时重读数据库，不要求用户重启 App（PRD-DATA-026） |

## 4 Expo Router 路由规划

> 目录规划遵循 [ARCHITECTURE.md](./ARCHITECTURE.md)：`src/app` **只放路由与布局**，业务实现放在 `src/features`。

规划要点：

- 五个 Tab 各自拥有一个 `_layout.tsx` 定义的独立 Stack，详情页压在所属 Tab 的栈内，不共用一个全局栈。
- 全屏表单一律挂在**根 Stack** 上：`purchase/*`、`redeem/*` 与 `wishlist/*`。心愿单的列表页仍然是 `(tabs)/wishlist/index.tsx`，只有新增与编辑两个表单被提到根栈。`/wishlist/new`、`/wishlist/[wishId]/edit` 与 `/wishlist` 共用同一段 URL 前缀但分属两个导航器，不会产生第二套 Tab。
- `catalog` 只是代码与路由的内部名称，界面上一律显示「百科」。
- 原生冷启动时 Expo Router 会把初始路径固定为 `/`。由于首页位于 `home/` 而非 `(tabs)/index.tsx`，需要 `src/app/index.tsx` 把 `/` 指向 `/home`，`(tabs)/_layout.tsx` 同时设置 `initialRouteName = "home"`，两者共同保证默认启动进入首页。
- **百科详情只有一份页面实现，由两个薄路由复用**：`(tabs)/catalog/[entryId].tsx` 与 `(tabs)/wishlist/article/[entryId].tsx` 渲染的是同一个 `ArticleDetailScreen`，两个路由文件都只做参数路由与 screen 渲染，不复制正文、收藏逻辑与加入心愿逻辑。从百科首页进入走百科 Tab 的路由，从收藏文章进入走心愿单 Tab 的路由，详情始终压在**用户当前所在 Tab** 自己的栈上。
- 因此从收藏文章打开的文章，**所有返回方式落点一致**：页面返回按钮、iOS 侧滑、Android 实体返回键与原生栈弹出都只是弹掉栈顶，回到收藏文章视图。不使用来源查询参数，不使用 `beforeRemove` 或 `usePreventRemove` 重定向，不关闭侧滑，不做「先返回再跳转」的两段式导航，也不靠隐藏 Tab 栏模拟根路由。

| `/wishlist/new` | `articleSlug` | 由百科详情「加入心愿单」携带，用于预填名称与分类（PRD 第 11.5 节）。只是初始值，保存时不入库；标识失效时打开空白表单并给中性说明 |

### 4.3 导航规则

1. **表单覆盖 Tab 栏**：`purchase/*`、`redeem/*` 与 `wishlist/*`（新增与编辑心愿）挂在根 Stack 上而非 Tab 内，避免用户在填写中误切 Tab 丢失内容。判断标准是**页面在哪个导航器里**，不是它长什么样：不允许把表单留在 Tab 栈内、再用页面级样式把 Tab 栏藏起来。
2. **详情留在 Tab 栈内**：详情页保留 Tab 栏，便于用户在浏览后横向切换。
3. **成功后回到有意义的位置**：新增购买记录成功后进入该记录详情，而非退回列表顶部；核销成功后回到发起页并刷新余次。
4. **返回不丢数据**：全屏表单在有未保存内容时返回需二次确认。
5. **未登录可访问**：法律文本与关于页在未登录状态下可达（PRD-DATA-003）。
6. **无死链**：每个页面的"出口"列中的目标路由必须真实存在；R0 阶段未实现的页面以静态占位页承接，不允许点击无响应。
