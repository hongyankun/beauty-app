# 信息架构（Information Architecture）

本文件定义 App 的导航结构、页面清单与路由规划，回答"用户去哪里""从哪进""到哪出"，不定义数据实现方式。

相关文档：[产品需求](./PRODUCT_REQUIREMENTS.md) · [项目简介](./PROJECT_BRIEF.md) · [架构](./ARCHITECTURE.md) · [决策记录](./DECISIONS.md) · [路线图](./ROADMAP.md)

> **本文件只做规划，不创建任何 `src/` 下的路由文件。** 路由随功能开发逐步落地。

---

## 1 一级导航

App 使用五个一级 Tab，顺序固定：

| 序号 | Tab | 主要任务 | 承载的核心场景 |
| --- | --- | --- | --- |
| 1 | 首页 | 看概览、提醒与快捷操作 | S3 查看余次和有效期、S4 回顾 |
| 2 | 记录 | 管理套餐与核销历史 | S1 购买后录入、S2 完成后核销 |
| 3 | 百科 | 搜索与了解医美知识 | S5 查询项目、仪器、材料知识 |
| 4 | 心愿单 | 管理想做的项目与收藏 | S6 收藏和记录想做项目 |
| 5 | 我的 | 管理账号与数据 | S7 换机与恢复 |

导航原则：

- 页面详情使用**栈式导航**进入，每个 Tab 拥有独立导航栈。
- 新增与编辑以**独立全屏页面**为主，覆盖 Tab 栏，避免误触丢失填写内容。
- 仅将日期选择、二次确认、单条核销等轻量交互作为**弹层**。
- 任何页面都必须有明确的返回路径，不存在死链。

│   └── 收藏列表

├── 我的 Tab
│   ├── 我的
│   ├── 提醒设置                        （R4）
│   ├── 数据导入导出                    （R2）
│   ├── 账号与注销                      （R2）
│   ├── 法律文本（隐私政策 / 用户协议 / 免责声明）
│   ├── 关于 App

## 3 页面清单

字段说明：**阶段**列中"是"表示属于第一阶段（R0 静态原型 + R1 本地闭环）需要落地的路由；"静态占位"表示第一阶段只建路由与静态页面，不实现业务逻辑。

### 3.1 首页 Tab

#### 3.1.1 首页总览

| 项 | 内容 |
| --- | --- |
| 目的 | 让用户在打开 App 的三秒内知道"还有什么没用完""接下来要做什么" |
| 入口 | App 启动默认页；任意 Tab 点击"首页" |
| 出口 | 新增购买记录、快速核销、记录列表（带筛选）、核销历史、消费统计、百科首页、心愿单列表 |
| 关键操作 | 新增购买记录；快速核销；点击待核销/临期数字跳转到对应筛选结果；查看最近一次核销 |
| 数据依赖 | 待核销项目数、剩余总次数、临期套餐数、最近三条核销 |
| 空状态 | 引导添加第一条购买记录，并说明录入后可管理剩余次数；不显示 0 值卡片堆叠 |
| 错误状态 | 优先展示本地缓存并标注"可能不是最新"，提供重试；无缓存时展示错误说明与重试按钮 |
| 阶段 | 是 |

#### 3.1.2 消费统计

| 项 | 内容 |
| --- | --- |
| 目的 | 按购买与核销两种口径回顾消费分布 |
| 入口 | 首页"消费概览"入口 |
| 出口 | 返回首页；从某一维度下钻到记录列表（带筛选） |
| 关键操作 | 切换统计口径（按购买 / 按核销）；切换年份与月份；按分类、项目、机构查看分布 |
| 数据依赖 | 购买记录、有效核销记录、项目分摊单价 |
| 空状态 | 无记录时引导录入；所选区间无数据时提示"该区间没有记录"，不回退全量 |
| 错误状态 | 展示失败说明与重试，不展示不完整的图表 |
| 阶段 | 否（R4） |

### 3.2 记录 Tab

#### 3.2.1 记录列表

| 项 | 内容 |
| --- | --- |
| 目的 | 集中管理全部套餐，快速定位"还没做完的" |
| 入口 | 记录 Tab；首页各统计数字跳转（携带预设筛选） |
| 出口 | 购买记录详情、新增购买记录、快速核销、核销历史 |
| 关键操作 | 切换套餐视图 / 项目余次视图；筛选（全部、待核销、已用完、临期、已过期）；按套餐名、项目名、机构名搜索；按分类、机构、城市筛选；清除筛选 |
| 数据依赖 | 购买记录、套餐项目、各项目派生剩余次数、有效期 |
| 空状态 | 区分"从未录入"（引导新增）与"当前筛选无结果"（提供清除筛选入口） |
| 错误状态 | 展示错误说明与重试；已缓存列表继续可见可滚动 |
| 阶段 | 是 |

#### 3.2.2 购买记录详情

| 项 | 内容 |
| --- | --- |
| 目的 | 查看单个套餐的完整信息与使用情况 |
| 入口 | 记录列表；首页最近记录；心愿单完成后创建的记录 |
| 出口 | 编辑购买记录、快速核销、百科详情（项目关联条目时）、返回列表 |
| 关键操作 | 编辑套餐；对有余次的项目发起核销；查看与撤销单条核销；删除套餐（二次确认并显示受影响数量） |
| 数据依赖 | 套餐基础信息、项目列表及派生次数、该套餐全部核销记录 |
| 空状态 | 尚无核销记录时提示"还没有核销记录"，并给出核销入口 |
| 错误状态 | 加载失败展示重试；删除或撤销失败保留原状态并说明原因，不假装成功 |
| 阶段 | 是 |

#### 3.2.3 核销历史

| 项 | 内容 |
| --- | --- |
| 目的 | 以时间维度回顾做过的项目 |
| 入口 | 首页"最近记录"；记录列表工具栏 |
| 出口 | 购买记录详情；返回 |
| 关键操作 | 按日期倒序浏览；按分类、项目、机构筛选；查看总次数、平均间隔天数与最近日期 |
| 数据依赖 | 有效核销记录、所属项目与套餐、机构快照 |
| 空状态 | 提示尚无核销记录并引导先录入套餐 |
| 错误状态 | 展示错误说明与重试 |
| 阶段 | 是 |
| 约束 | 间隔天数**只作事实展示**，不出现"正常""过快""建议复购"等评价或推销表述（PRD-NFR-003） |

### 3.6 全屏表单层

这些页面覆盖 Tab 栏，从任意 Tab 均可进入，返回时回到来源页。

#### 3.6.1 新增购买记录

| 项 | 内容 |
| --- | --- |
| 目的 | 录入一次购买及其包含的项目 |
| 入口 | 首页"新增购买记录"；记录列表"新增"；心愿标记完成后的创建流程 |
| 出口 | 保存成功进入购买记录详情；取消返回来源页 |
| 关键操作 | 填写套餐字段；选择或新增机构；动态增删项目行；从百科选择或自定义项目名称；保存 |
| 数据依赖 | 百科条目检索、已录入机构列表 |
| 空状态 | 项目区默认给出一行空项目，并说明至少需要一个项目 |
| 错误状态 | 校验失败定位到具体字段；保存失败保留全部已填内容并可重试（PRD-ERR-003） |
| 阶段 | 是 |
| 约束 | 总价与分摊差额超过 1 元时提示但允许保存；金额以元输入、按分存储 |

| 项 | 内容 |

#### 3.6.3 快速核销

| 项 | 内容 |
| --- | --- |
| 目的 | 用最少步骤记录"我做了一次" |
| 入口 | 首页快捷核销；记录列表项目余次视图；购买记录详情的项目行 |

### 4.2 查询参数约定

不为筛选状态单独建路由，统一使用查询参数，便于首页数字直接跳转：

| 路由 | 参数 | 取值 |
| --- | --- | --- |
| `/(tabs)/records` | `view` | `package`（套餐视图，默认） / `item`（项目余次视图） |
| `/(tabs)/records` | `filter` | `all` / `pending` / `used` / `expiring` / `expired` |
| `/(tabs)/records` | `q` | 搜索关键词 |
| `/(tabs)/records/history` | `itemId`、`category`、`institutionId` | 可选筛选维度 |
| `/(tabs)/catalog/search` | `q`、`type` | 关键词、内容类型 |
| `/(tabs)/catalog/search` | `pickFor` | 从表单进入时的回填目标，用于选中后返回并回填项目名称 |
| `/purchase/new` | `fromWishId` | 由心愿标记完成进入时携带，用于带入初始信息 |
| `/redeem/[purchaseItemId]` | `from` | 来源页标识，用于成功后返回正确位置 |

### 4.3 导航规则

1. **表单覆盖 Tab 栏**：`purchase/*` 与 `redeem/*` 挂在根 Stack 上而非 Tab 内，避免用户在填写中误切 Tab 丢失内容。
2. **详情留在 Tab 栈内**：详情页保留 Tab 栏，便于用户在浏览后横向切换。
3. **成功后回到有意义的位置**：新增购买记录成功后进入该记录详情，而非退回列表顶部；核销成功后回到发起页并刷新余次。
4. **返回不丢数据**：全屏表单在有未保存内容时返回需二次确认。
5. **未登录可访问**：法律文本与关于页在未登录状态下可达（PRD-DATA-003）。
6. **无死链**：每个页面的"出口"列中的目标路由必须真实存在；R0 阶段未实现的页面以静态占位页承接，不允许点击无响应。
