## 1 文档定位

本文件定义 App 的**视觉语言**：颜色、字体、间距、圆角、阴影、图标、卡片、表单、按钮、状态表达与导航样式。

它回答"长什么样"，不回答"有什么功能"和"页面怎么组织"：

- **功能与业务规则**以 [PRODUCT_REQUIREMENTS.md](./PRODUCT_REQUIREMENTS.md) 为准。
- **页面结构与路由**以 [INFORMATION_ARCHITECTURE.md](./INFORMATION_ARCHITECTURE.md) 为准。
- **视觉语言**以本文件为准。

三者冲突时**不得自行判断**，必须停止并询问产品负责人。

本文件中的设计 Token 为**第一版暂定值，后续以真机视觉验收为准**。调整 Token 需同步更新本文件，不得在页面里写死一次性色值。

参考视觉稿：<https://b28750c3d6954279b9f502f8d3802903.app.workbuddy.link/>

> 该链接仅供参考**视觉风格**，可能随时失效，不作为长期依据；本文件的文字描述才是基线。**不得从该网页继承任何技术架构、页面结构或实现方式**，也不得照搬原网页版的信息架构（见 [ADR-004](./DECISIONS.md#adr-004-从-0-重建不复用原-beauty_tracker-代码)）。

## 2 品牌与视觉目标

产品方向为 **iBeauty 1.0 / Fresh Mint**。

目标气质：

- **干净、克制、私人**，像一份自己的台账，不像商城或营销页。
- **轻医疗美学的生活感**：有医疗类产品的清爽与秩序，但不冷、不像病历系统。
- 用留白和层级表达质感，**不用装饰元素堆砌**。

暖白底 + 薄荷绿主色 + 珊瑚色警示，构成全部视觉识别。界面应让用户注意到**自己的数据**（剩余次数、金额、日期），而不是注意到界面本身。

## 3 色彩系统

| Token | 色值 | 用途 |
| --- | --- | --- |
| `backgroundWarm` | `#FAFCF9` | 页面底色，暖白 |
| `surface` | `#FFFFFF` | 卡片、弹层、输入框底色 |
| `mintStrong` | `#3F806C` | 主色深色变体：实心主按钮底色、选中 Tab、可点击的薄荷绿文字等需要足够对比度的交互前景 |
| `mintPrimary` | `#8FCDB8` | 主色：装饰性图标、较浅强调与非文字视觉元素 |
| `mintLight` | `#E6F5ED` | 主色浅底：标签、选中背景、轻量强调区 |
| `coral` | `#F4A39A` | 警示：临期、过期、删除、错误 |
| `coralLight` | `#FDE7E3` | 警示浅底：警示标签与提示条背景 |
| `textPrimary` | `#30322F` | 主文字：标题、正文、金额 |
| `textSecondary` | `#6E746F` | 次要文字：标签、辅助说明、占位符 |
| `borderLight` | `#E4EAE6` | 分隔线、卡片描边、输入框描边 |

### 3.1 用色规则

- 页面底色使用 `backgroundWarm`，内容块使用 `surface`，**依靠底色与卡片的微弱色差分层**，不靠重阴影。
- 薄荷绿是唯一主色，按对比度需求分成三个 Token，职责不可互换：
  - `mintStrong` 用于**必须被准确辨认的交互前景**：实心主按钮底色（配白色文字）、当前选中的 Tab 图标与文字、可点击的薄荷绿色文字、选中 Chip 的描边与对勾。
  - `mintPrimary` 用于**装饰性与非文字元素**：空状态插图图标、头像占位图标、轻量强调。它对浅底的对比度不足以承载文字，**不得**用于按钮文字、Tab 文字或任何需要阅读的内容。
  - `mintLight` 用于**浅色底**：标签底、选中区域底色、轻量强调区，其上的文字仍使用 `textPrimary` 或 `mintStrong`。
- **一屏之内主色的实心填充面积应当很小**，通常只有一个主按钮。引入 `mintStrong` 不意味着把界面上所有薄荷绿替换成深色，整体仍保持清爽柔和。
- `coral` 只用于需要用户注意的负向状态（临期、过期、删除、校验失败），**不用于装饰**，也不用于促销。
- 大面积着色一律使用 `mintLight` / `coralLight` 浅底 + 深色文字，不使用饱和色块铺底，不使用渐变，不出现大面积深绿色。
- 状态不得只用颜色表达，必须同时有文字或图标（PRD-NFR-005）。引入 `mintStrong` 后这条依然成立：选中 Chip 同时具备浅底、描边与对勾，不靠颜色单独区分。
- 文字与背景需满足足够对比度；`textSecondary` 不用于正文长段落。

> `mintStrong` 是第一次 iOS 模拟器人工视觉验收后补充的可访问性修正。验收确认整体方向可用，但原 `mintPrimary` 作为按钮底色配白字、以及作为可点击文字色时对比度不足，因此拆出一个专供交互前景使用的深色变体，原有 Token 的用途保持不变。

## 4 字体与数字排版

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| 正文 | iOS 使用 PingFang SC，Android 使用系统默认无衬线 | 标题、正文、标签、按钮、表单 |
| 数字强调 | Georgia 或系统衬线回退 | 金额、剩余次数、统计关键数值 |

### 4.1 规则

- **最多两种字体角色**，不引入第三种。
- 不自带字体文件，使用系统字体，避免包体增大与授权问题。
- 衬线体**只用于数值**（金额、次数、统计数字），不用于中文正文、不用于按钮文字。
- 金额按整数分存储、以元展示（[ADR-006](./DECISIONS.md#adr-006-金额使用整数分)），展示格式为 `¥1,280.00`。
- 数字使用等宽或表格数字对齐方式，保证列表中金额与次数纵向对齐。
- 层级靠**字号与字重**建立，不靠颜色：标题加粗，正文常规，辅助说明用 `textSecondary`。
- 必须支持系统字体缩放，放大到最大档时核心信息不被截断（PRD-NFR-006）。

## 5 间距体系

基础栅格为 **8pt**，允许 4pt 作为半格微调。

允许的间距值：**4 / 8 / 12 / 16 / 20 / 24 / 32**。不使用列表以外的数值。

常用约定：

| 场景 | 间距 |
| --- | --- |
| 页面左右安全边距 | 16 |
| 卡片内部内边距 | 16 |
| 卡片之间的垂直间距 | 12 |
| 区块之间的垂直间距 | 24 |
| 表单项之间的垂直间距 | 20 |
| 标签与其输入框之间 | 8 |
| 图标与相邻文字之间 | 8 |
| 紧密关联的两行文字之间 | 4 |

**留白是本设计的主要表达手段**。宁可减少一屏的信息密度，也不要压缩间距。

## 6 圆角、边框与阴影

### 6.1 圆角

允许的圆角值：**8 / 12 / 16 / 20**。

| 元素 | 圆角 |
| --- | --- |
| 标签、徽标、小控件 | 8 |
| 输入框、次级按钮 | 12 |
| 卡片、主按钮 | 16 |
| 底部弹层顶部、大面积容器 | 20 |

不使用全圆角胶囊形状作为主要按钮样式。

### 6.2 边框

- 统一使用 **1pt** 细边框，颜色 `borderLight`。
- 卡片优先使用"白底 + 细边框"，而不是"白底 + 阴影"。
- 分隔线使用同色 1pt，左侧与内容左对齐，不通栏贯穿。

### 6.3 阴影

- 只允许**极轻阴影**：小偏移、大模糊、低不透明度，视觉上近似"纸张微微浮起"。
- 阴影只用于**浮层**（底部弹层、浮动按钮、吸顶栏滚动后的分界）。
- 常规卡片**不加阴影**。
- 不使用多层阴影、不使用彩色阴影、不使用内阴影。

## 7 图标规则

- 使用**线性图标**，统一描边粗细（约 1.5–2pt），不使用面性或双色图标。
- 标准尺寸：列表与表单内 20，导航栏与 Tab 24，空状态插图区 32 以上。
- 图标颜色默认 `textSecondary`；选中、可点击或需要强调时使用 `mintStrong`；纯装饰性图标可用 `mintPrimary`；警示时使用 `coral`。
- **图标不单独承担语义**：功能入口必须配文字标签；纯图标按钮必须有屏幕阅读器标签（PRD-NFR-004）。
- 不使用拟物图标、不使用品牌色渐变图标、不使用表情符号代替图标。

---

## 8 卡片与列表规则

### 8.1 卡片

- 白底 `surface`、圆角 16、1pt `borderLight` 边框、内边距 16。
- 一张卡片承载**一个对象**（一个套餐、一条核销、一条心愿），不把多个对象塞进同一张卡。
- 卡片内信息优先级：**主标题 → 关键数值 → 辅助信息 → 操作**，自上而下。
- 关键数值（剩余次数、金额）使用衬线数字 + `textPrimary`，必要时配 `mintLight` 浅底标签。
- 状态标签置于右上或标题右侧，不抢占主标题位置。

### 8.2 列表

- 列表项之间使用 12 间距的卡片，或使用 1pt 分隔线的紧凑行，**同一页面内只用一种**。
- 长列表需支持在数百条数据下顺畅滚动（PRD-NFR-007），不做逐项动画。
- 列表首次加载展示**骨架屏**，翻页展示局部加载指示。
- 空状态必须区分"从未录入"与"当前筛选无结果"，后者提供清除筛选入口。

---

## 9 表单规则

- 采用**标签在上、输入框在下**的纵向布局，不使用左右对齐的两栏表单。
- 输入框：白底、圆角 12、1pt `borderLight` 边框，高度不小于 44pt。
- 聚焦态：边框变为 `mintStrong`，不使用外发光。
- 错误态：边框变为 `coral`，下方以 `coral` 文字说明具体原因，**不只变红**。
- 占位符使用 `textSecondary`，且**不能替代标签**——每个输入都必须有可见标签并与输入关联。
- 必填项标注清晰；金额输入以元为单位，键盘为数字键盘。
- 机构、项目名称等字段使用**可搜索的选择器 + 新增**形态，而非纯文本输入框。
- 长表单在切换页面或保存失败时**不得清空已填内容**（PRD-ERR-003）。
- 提交按钮固定在底部安全区上方，提交中显示进行中状态并禁用。

## 10 按钮规则

| 类型 | 样式 | 用途 |
| --- | --- | --- |
| 主按钮 | `mintStrong` 实心填充、白色文字、圆角 16 | 每屏最多一个，承载主要动作 |
| 次按钮 | 白底、1pt `borderLight` 边框、`textPrimary` 文字、圆角 12 | 辅助动作 |
| 文字按钮 | 无底无边框、`mintStrong` 文字 | 轻量跳转、"查看全部" |
| 危险按钮 | 白底、`coral` 边框与文字；确认删除时可用 `coral` 实心 | 删除、注销 |

规则：

- **每屏只有一个主按钮**。出现两个实心主按钮即为违规。
- 所有按钮触控区域不小于 **44 × 44pt**。
- 禁用态降低不透明度并同时给出**文字说明原因**（例如余次为 0 时说明无法核销）。
- 加载态在按钮内显示进行中指示并禁用，防止重复提交（PRD-RED-005）。
- 按钮文案使用动词短语，不使用"确定""提交"之外无信息量的词时优先具体化，例如"保存套餐""确认核销"。

## 11 状态表达

| 状态 | 表达 |
| --- | --- |
| 正常 / 有余次 | `mintLight` 浅底标签 + `textPrimary` 文字 |
| 临期 | `coralLight` 浅底标签 + `coral` 文字 + 明确文案（例如"30 天内到期"） |
| 已过期 | 灰度处理 + `textSecondary` 文字 + "已过期"文案 |
| 已用完 | 灰度处理 + "已用完"文案，不使用警示色 |
| 已作废 | 记录保留并置灰，标注"已撤销"，不使用技术术语 |
| 错误 | `coral` 文字说明 + 重试入口 |
| 离线 | 顶部或卡片内的中性提示条，说明"可能不是最新" |

规则：

- 状态**必须同时有文字**，不得仅靠颜色或圆点区分（PRD-NFR-005）。
- 空状态给出**一句引导 + 一个动作按钮**，不只显示"暂无数据"。
- 界面不出现 `active`、`void` 等技术术语（PRD-RED-010）。
- 提示文案保持中性陈述，不出现"建议复购""该做第二次了"等指令性或推销性表述（PRD-NFR-002）。

## 12 底部导航规则

- 五个一级 Tab，顺序固定：**首页、记录、百科、心愿单、我的**。
- 样式：`surface` 白底、顶部 1pt `borderLight` 分隔线、适配底部安全区。
- 每项为**线性图标 + 文字标签**，标签不可省略。
- 选中态：图标与文字变为 `mintStrong`；未选中为 `textSecondary`。**不使用胶囊背景、不放大图标、不加指示条。**
- 不在 Tab 栏中放置凸起的中央加号按钮；新增入口放在页面内。
- 全屏表单（新增购买、编辑购买、快速核销）**覆盖 Tab 栏**，防止填写中误切。
- 第一阶段使用 Expo Router 的**经典 `Tabs`**（React Navigation bottom-tabs），不使用 `NativeTabs`：上述白底、1pt 顶部分隔线、`mintStrong` 选中态、强制显示文字标签、无胶囊背景与指示条等要求，在 iOS 原生 UITabBar 上无法逐项控制，经典 `Tabs` 才能在 iOS 与 Android 上得到一致且可控的颜色、边框与 Tab 样式。

## 13 五个一级 Tab 的视觉重点

| Tab | 视觉重点 |
| --- | --- |
| 首页 | 少而大。以 2–3 个关键数字（待核销、剩余总次数、临期数）为视觉中心，衬线数字 + 大量留白；下方是两个快捷入口与最近记录，不堆图表 |
| 记录 | 密而清。以卡片列表为主体，强调套餐名与剩余次数的对齐与可扫读；筛选条克制，选中项用 `mintLight` 浅底标签 |
| 百科 | 内容优先。大字号标题、舒适行距、充足留白，接近阅读界面；分类入口使用浅底标签而非彩色色块 |
| 心愿单 | 轻松、有呼吸感。卡片间距更大，状态标签是主要的视觉区分手段；不使用促销式强调 |
| 我的 | 极简。分组列表 + 1pt 分隔线，无卡片阴影；危险操作（注销、删除数据）单独成组并使用危险按钮样式 |

## 14 可访问性与触控要求

- 所有可点击元素的触控区域不小于 **44 × 44pt**，即使视觉尺寸更小。
- 相邻可点击元素之间至少保留 8pt 间距。
- 表单输入与标签必须关联；纯图标控件必须提供屏幕阅读器标签（PRD-NFR-004）。
- 不只依赖颜色传达信息（PRD-NFR-005）。
- 支持系统字体缩放，核心信息在最大档下不被截断（PRD-NFR-006）。
- 文字与背景保持足够对比度；禁用态不得低到无法辨读。
- 所有用户可见文字使用简体中文（PRD-NFR-001）。

## 15 禁止事项

- **禁止使用渐变**，包括背景渐变、按钮渐变、图标渐变与文字渐变。
- 禁止使用重阴影、多层阴影、彩色阴影与内阴影。
- 禁止大面积饱和色块铺底。
- 禁止在一屏内出现两个实心主按钮。
- 禁止引入第三种字体角色，禁止自带字体文件。
- 禁止使用本文件第 3 章之外的颜色，或第 5、6 章之外的间距与圆角数值。
- 禁止用颜色单独表达状态。
- 禁止在 Tab 栏使用凸起中央按钮、胶囊选中背景或指示条。
- 禁止照搬原网页版的信息架构、页面布局与技术实现。
- 禁止出现营销式视觉：促销角标、倒计时、红点催促、"限时"类强调。
- **禁止未经确认自行增加照片、相机或相册入口**（[ADR-008](./DECISIONS.md#adr-008-第一版不做照片功能)）。
- 禁止在界面中把 AI 呈现为医生形象或使用白大褂、听诊器等医疗身份视觉符号（[ADR-009](./DECISIONS.md#adr-009-ai-定位为记录与科普助手不是医生)）。

## 16 后续实现与验收方法

### 16.1 实现方式

- 设计 Token 落地为 `src/theme` 下的常量（见 [ARCHITECTURE.md 第六节](./ARCHITECTURE.md#六推荐目录结构)），页面**不得硬编码色值、间距与圆角**。
- Token 命名与本文件第 3 章保持一致，便于文档与代码互查。
- 不引入 UI 组件库（[ADR-011](./DECISIONS.md#adr-011-暂不引入状态管理和-ui-组件库等待具体需求)）。

### 16.2 当前验收状态

- 当前视觉方向已通过**第一次 iOS 模拟器人工验收**：整体方向、五个页面布局与 Token 体系确认可用，本轮只做 `mintStrong` 对比度修正，不做整体重新设计。
- 模拟器验收**不等于**通过第 16.3 节的全部检查。正式功能接入后，仍需在真机上复验暖白底与白卡片的层次，并重新完成对比度、字体缩放与屏幕阅读器的可访问性检查。
- 开发期临时挂在模拟器上的调试入口（例如开发者菜单按钮）不属于 App UI，不计入本文件的规则与验收范围。

### 16.3 验收方法

UI 任务完成后按以下方式检查：

1. 取页面截图，逐项比对第 3 至第 12 章的规则。
2. 检查是否出现渐变、重阴影、第二个实心主按钮、超出 Token 的色值或间距。
3. 打开系统字体最大档，确认核心信息不被截断。
4. 开启屏幕阅读器，确认纯图标控件可被朗读。
5. 检查状态是否同时具备文字表达。
