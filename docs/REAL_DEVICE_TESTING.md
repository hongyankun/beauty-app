# 真机试用说明（美迹 / iBeauty）

这份文档写给**在 iPhone 上试用美迹的人**，不需要任何开发经验。

相关文档：[产品需求](./PRODUCT_REQUIREMENTS.md) · [信息架构](./INFORMATION_ARCHITECTURE.md) · [路线图](./ROADMAP.md)

当前阶段：**本地试用版**。App 通过 Expo Go 在两台 iPhone 上运行，数据全部保存在各自的手机里，没有账号，也没有云同步。

---

## 1 现在怎么用

### 1.1 准备

1. 两台 iPhone 都从 App Store 安装 **Expo Go**。
2. 两台 iPhone 和运行开发服务的 Mac **连在同一个 Wi-Fi** 上。
3. 两台 iPhone 的 Expo Go 都**登录同一个 Expo 账号**，并且与 Mac 上使用的账号一致。

在 Mac 上确认账号：

```bash
npx expo whoami
```

预期输出的账号为 `bronxshong`。如果显示的是别的账号或者提示未登录，先用 `npx expo login` 登录成正确的账号，再继续。

### 1.2 启动

在 Mac 上，项目目录里执行：

```bash
NODE_OPTIONS=--dns-result-order=ipv4first npx expo start --clear --lan
```

终端里会出现一个二维码。用 **iPhone 自带的相机**对着它扫一下，按提示在 Expo Go 里打开即可。

两台 iPhone 扫同一个二维码，各自打开一份 App。

> 命令里的 `--clear` 会清掉打包缓存，启动稍慢一点，但能避免改动没生效的问题。
> `NODE_OPTIONS=--dns-result-order=ipv4first` 是为了让 Mac 优先用 IPv4 地址对外提供服务，
> 在很多家用路由器上这一条能省掉大量连不上的麻烦。

## 2 连不上时按顺序检查

出现"连接超时""Something went wrong"或者一直停在加载条时，**按下面的顺序**逐条核对，不要跳着试：

1. **Expo Go 里登录的账号，和 Mac 上 `npx expo whoami` 显示的账号是不是同一个。**
2. **手机和 Mac 是不是在同一个 Wi-Fi 上。** 注意手机不要走蜂窝网络，也不要连到访客网络或另一个频段的独立 SSID。
3. **Mac 的防火墙。** 打开「系统设置 → 网络 → 防火墙」，确认它没有拦截传入连接；如果开着，允许 Node 接收传入连接。
4. **Metro 还在不在跑。** Mac 终端里那个启动命令必须一直开着，窗口关掉或者按了 Ctrl-C，手机就会立刻失去连接。
5. **扫的是不是最新的二维码。** 重启过服务之后旧二维码就失效了，需要重新扫终端里当前显示的那个。

五条都核对过仍然连不上，改用隧道模式启动：

```bash
NODE_OPTIONS=--dns-result-order=ipv4first npx expo start --clear --tunnel
```

隧道模式不要求手机和 Mac 在同一个网络，但速度会慢一些。

> 不要为了连上而关闭手机或 Mac 的安全设置，也不要把路由器改成没有密码的开放网络。
> 连不上是配置问题，不是安全机制的问题。

## 3 两台手机上的数据是什么关系

**两台 iPhone 的数据完全独立。**

- 每台手机的 Expo Go 里各有一份自己的本地数据库。
- 在 A 手机上新增套餐、记录核销、添加机构或心愿，**不会**出现在 B 手机上。
- 现在没有账号体系，也没有云同步，两台手机之间不存在任何自动同步。

如果需要让两台手机拿到同一份数据，只能手动搬一次：

1. 在 A 手机打开「我的 → 数据备份 → 导出备份」，得到一个 `ibeauty-backup-…json` 文件。
2. 通过 AirDrop（或任意你信任的方式）把这个文件传到 B 手机。
3. **先在 B 手机上导出一份它自己的当前数据。** 下一步会把它覆盖掉。
4. 在 B 手机打开「我的 → 数据备份 → 选择备份文件」，选中刚收到的文件，核对摘要，再点「恢复这份备份」。

关于恢复，有一点必须清楚：

> **恢复是整体覆盖，不是合并。**
> 恢复之后，B 手机的数据会变成 A 手机导出那一刻的样子；B 手机原来有、而备份里没有的记录会被删除，且**无法在 App 内撤销**。
> 所以第 3 步的"先导出一份自己的数据"不是客套话。

备份文件里是完整的个人消费记录和机构信息，请只传给自己信任的设备，并保存在你信任的位置。

## 4 Expo Go 试用的限制

- **Mac 上的开发服务必须一直开着。** 关掉终端、Mac 睡眠或断网之后，手机上的 App 就打不开了。它不是一个能独立运行的应用。
- **Expo Go 是开发试用容器，不是安装到手机上的正式 App。** 手机桌面上看到的是 Expo Go 的图标，不是美迹的图标。
- **现在没有 TestFlight 邀请，也没有上架 App Store。** 想让别人试用，只能按第 1 节的方式加入同一个 Expo 账号。
- **删除 Expo Go、或在 Expo Go 里清除这个项目的数据，本机的试用数据会一起消失。** 这份数据只存在这台手机上，没有任何云端副本。所以：**试用期间请定期导出备份**，尤其是在删除 Expo Go、更换手机或重装系统之前。
- 想要一个能独立打开、不依赖 Mac 的 App，需要做 development build 或加入 Apple Developer Program。这两件事都**不在当前阶段**，见第 5 节。

## 5 关于免费 Apple 账号的边界

有人会问："能不能不花钱，直接把 App 装到手机上？"

技术上，免费的 Apple 个人开发者身份（Personal Team）可以通过 Xcode 把 App 装到少数几台自己的设备上。但它有几个现实约束：

- 免费签名通常需要**定期重新签名**，过一段时间 App 就会打不开。
- 需要在本机生成原生工程、连数据线、用 Xcode 操作，对非技术使用者不友好。

**本轮不采用这种方式。** 当前阶段不修改原生工程、不生成任何证书、不要求付费 Apple Developer 账号，试用一律走 Expo Go。

TestFlight、独立 development build 与 App Store 发布都属于后续阶段的工作，见 [ROADMAP](./ROADMAP.md) Phase 7。

> 不要把 Apple ID、密码、设备 UDID、证书或描述文件写进这个仓库或任何文档里。
> 试用过程中需要交换这类信息时，走私下渠道，不留在代码库中。
