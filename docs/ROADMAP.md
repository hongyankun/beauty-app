## Phase 0 工程初始化与基线

**目标**：建立可靠、可重复、可被多个开发会话共享的工程基线。

**主要交付物**
- Expo SDK 57 + Expo Router + TypeScript strict 工程
- ESLint（`eslint-config-expo` flat config）
- `.gitignore` 覆盖环境变量与敏感文件
- 项目文档：PROJECT_BRIEF、ARCHITECTURE、DECISIONS、ROADMAP
- CLAUDE.md 开发规则

**完成标准**
- `npm run lint` 通过
- `npx tsc --noEmit` 通过
- `npx expo-doctor` 全部检查通过
- iOS 模拟器可正常启动
- 文档齐备且相互引用正确

**暂不处理**：CI 流水线、测试框架、EAS 构建配置、应用标识符。

## Phase 1 移动端信息架构与静态页面

**目标**：把五个 MVP 模块的骨架搭出来，确定导航结构与页面层级，先解决"去哪里"，不解决"数据从哪来"。

**主要交付物**
- 首页、记录、医美百科、心愿单与收藏、我的 —— 五个入口的路由与布局
- 核心闭环涉及的页面占位：套餐列表、套餐详情、新增套餐、核销
- 基础视觉规范（颜色、间距、字号）落到 `constants`
- 清理 Expo 模板示例文件

**完成标准**
- 全部页面可通过导航到达，无死链
- 使用写死的示例数据渲染，不接任何持久化
- lint 与 tsc 通过

**暂不处理**：真实数据、持久化、表单校验、账号、动效打磨。

## Phase 2 核心数据模型与本地业务闭环

**目标**：跑通第一阶段核心闭环，数据先落本地，但结构按未来要同步到云端来设计。

**主要交付物**
- **（已完成）** `db` 层基础：expo-sqlite 依赖、版本化迁移机制、数据库 Provider 与启动时自动初始化（[ADR-013](./DECISIONS.md#adr-013-本地持久化使用-expo-sqlite)）
- **（已完成）** V1 表结构：profiles / institutions / purchases / purchase_items / redemption_records，含外键、约束与索引
- Purchase / PurchaseItem / Redemption 的领域模型与类型定义（当前只有数据库行类型）
- repository 实现 + 为同步预留的操作队列结构
- **（已完成）** Institution 的新增、复用、编辑、归档与恢复，以及"我的"下的机构管理中心（[ADR-014](./DECISIONS.md#adr-014-机构作为可复用的独立实体)，见 [PRD 第 5A.3 节](./PRODUCT_REQUIREMENTS.md#5a3-机构管理编辑归档与恢复)）
- 剩余次数的派生计算逻辑（由购买数量与有效核销记录算出，不可直接改写）
- 套餐永久删除与核销作废的业务操作与确认 UI（规则已定，见 [ADR-016](./DECISIONS.md#adr-016-套餐永久删除核销记录使用作废机制)；表结构已就绪，业务逻辑与界面未实现）
- 完整闭环：新增套餐 → 添加项目 → 查看详情 → 核销 → 余次更新 → 首页统计更新
- **（已完成）** 医美百科首版：四个浏览分类、随 App 本地打包的文章正文、首页内嵌搜索与分类筛选、文章详情与资料来源（见 [PRD 第 10 章](./PRODUCT_REQUIREMENTS.md#10-百科模块)）。该模块只读、不依赖网络；正文不入库，独立搜索页与内容扩充仍在 Phase 4
- **（已完成）** V2 表结构与心愿单首版：新增 `wishlist_items` 表，心愿单列表、新增、编辑与永久删除（见 [PRD 第 11 章](./PRODUCT_REQUIREMENTS.md#11-收藏与心愿单)）。只有名称必填，意向机构只能选已有机构，不存机构名称快照；状态、优先级与「标记完成 → 创建购买记录」仍在 Phase 4
- **（已完成）** V3 表结构与百科收藏首版：新增 `catalog_favorites` 表（只保存 `profile_id` + `article_slug`，正文仍在本地静态内容里），文章详情的收藏与取消收藏、心愿单 Tab 下的「收藏文章」视图，以及从文章「加入心愿单」时对新增心愿表单的预填（见 [PRD 第 11.1 节](./PRODUCT_REQUIREMENTS.md#111-收藏)）。收藏列表的分类筛选、下架标注、收藏文件夹与云同步仍在后续阶段
- **（已完成）** 本地数据备份导出：把当前档案的机构、套餐、套餐项目、核销记录、心愿与百科收藏导出为一个带版本号的 JSON 文件，经系统分享面板交给用户自己保存（见 [PRD 第 15.2 节](./PRODUCT_REQUIREMENTS.md#152-数据备份导出与恢复)）。不改表结构，不产生新迁移，不上传到任何服务器
- **（已完成）** 从本地备份文件恢复数据：选择一个备份 JSON → 校验 → 看摘要 → 二次确认 → 在一个独占事务内**整体覆盖**当前档案（见 [PRD 第 15.2.6 节](./PRODUCT_REQUIREMENTS.md#1526-从备份恢复)、[ADR-019](./DECISIONS.md#adr-019-从备份恢复采用整体覆盖--单事务备份文件一律当作不可信输入)）。备份文件当作不可信输入：10 MiB 上限、完整结构校验、不执行文件中的任何 SQL、不因文件内容改动 `PRAGMA user_version`；失败整体回滚，数据库逐行不变。合并恢复、选择性恢复、ZIP 与加密备份、自动与定时备份均不在范围内
- **（已完成）** 产品名称基线与双 iPhone 真机试用：产品工作名称定为 **美迹 / iBeauty**，Expo 用户可见名称改为「美迹」，「我的」页脚展示产品名、`iBeauty · 本地试用版` 与版本号，导出备份的用户可见文件名前缀改为 `ibeauty-backup-`（**备份协议、数据库文件名、schema 版本与 migration 均未变**，旧备份仍可恢复）。真机试用方式为**两台 iPhone 通过 Expo Go 扫码运行**，两台设备的数据各自独立、互不同步，搬运数据只能走「导出备份 → 传输 → 从备份恢复」，见 [REAL_DEVICE_TESTING.md](./REAL_DEVICE_TESTING.md)。**这只是开发期试用，不是发布**：没有 TestFlight 构建，没有独立安装包，Mac 上的开发服务停掉手机就打不开

**完成标准**
- 闭环全流程可用，App 重启后数据不丢
- 金额全程以整数分处理，无浮点参与
- 余次在任何路径下都与核销记录一致，不存在可直接编辑余次的入口
- lint 与 tsc 通过

**暂不处理**：多设备同步、账号、云端存储（本地备份的**导出与恢复**已在本阶段落地，见上；它是用户自己持有文件的单机退路，不是同步）。

## Phase 3 后端、账号与云同步

**目标**：引入服务端，把权威数据源迁到云端，本地降级为缓存。

**主要交付物**
- NestJS + PostgreSQL + Prisma 后端服务
- REST API + OpenAPI 文档
- Account 与 Profile 分离的账号体系与认证（数据模型层分离；第一版仍只有一个个人档案，不开放切换与多人管理，见 [ADR-015](./DECISIONS.md#adr-015-第一版只做个人档案不做多人)）
- 基于操作队列的同步机制与冲突处理策略
- 本地已有数据向账号迁移的方案

**完成标准**
- 用户可注册登录，数据随账号在多设备间保持一致
- 离线操作可在恢复网络后正确回放
- 用户只能访问自己的数据，权限有服务端校验
- 无任何全量覆盖式同步逻辑

**暂不处理**：多人共享账户、B 端接口、数据分析后台。

## Phase 4 百科、收藏与心愿单

**目标**：补齐高频使用场景，让低频记录之外有持续打开的理由。

**主要交付物**
- 医美百科的内容结构、分类与检索 —— **首版已在 Phase 2 落地**：四个浏览分类（基础认知、光电项目、注射项目、护理与安全）、随 App 本地打包的文章正文、首页内嵌搜索与分类筛选、文章详情与资料来源，见 [PRD 第 10 章](./PRODUCT_REQUIREMENTS.md#10-百科模块)。本阶段在其之上扩充内容、增加独立搜索页与相关条目跳转，并把浏览分类扩展到 PRD 第 10.1.2 节的五类长期内容类型体系
- 收藏功能 —— **首版已在 Phase 2 落地**（文章详情收藏与取消收藏、心愿单 Tab 下的「收藏文章」视图，见 [PRD 第 11.1 节](./PRODUCT_REQUIREMENTS.md#111-收藏)）。本阶段补齐收藏列表的分类筛选、条目下架后的标注，以及收藏与云端账号的同步
- 心愿单增强 —— **首版已在 Phase 2 落地**（列表、新增、编辑、永久删除，见 [PRD 第 11.2 节](./PRODUCT_REQUIREMENTS.md#112-心愿单wishlistitem)）；从百科详情「加入心愿单」的**预填**也已落地，但保存后的心愿与文章没有长期绑定。本阶段补齐 [PRD 第 11.4 节](./PRODUCT_REQUIREMENTS.md#114-后续版本)的内容：心愿状态与优先级、与百科条目的长期关联、标记完成后创建或关联一条购买记录

**完成标准**
- 百科内容可浏览、可检索、可收藏（浏览、检索与收藏首版已具备，本阶段补齐收藏列表筛选与下架标注）
- 心愿单可增删（首版已具备），并能与百科条目和记录模块建立关联（首版只有一次性预填，尚无长期关联）
- 内容中立客观，不含疗效承诺，不含机构导流

**暂不处理**：社区、评论、UGC、机构评分、内容推荐算法。

## Phase 5 提醒、统计与 AI 辅助

**目标**：在已有数据之上提供价值增量，降低套餐遗忘和浪费。

**主要交付物**
- 待核销与套餐到期的**推送提醒**，以及用户可配置的临期阈值（应用内的临期与过期提醒已在 Phase 2 落地，见 [PRD 第 8.4 节](./PRODUCT_REQUIREMENTS.md#84-临期与过期提醒)）
- 消费与使用情况统计
- AI 辅助：记录总结、待办提醒、一般性知识解释、面诊提问清单生成

**完成标准**
- 提醒准确，不误报不漏报
- 统计口径与记录数据完全一致
- AI 输出严格落在 [ADR-009](./DECISIONS.md#adr-009-ai-定位为记录与科普助手不是医生) 界定的范围内，具备越界拦截
- AI 相关的密钥不出现在客户端

**暂不处理**：复杂个性化推荐、基于用户画像的项目推荐。

---

## Phase 6 内测、安全和合规

**目标**：在面向真实用户前完成安全与合规检查。

**主要交付物**
- 隐私政策与用户协议
- 权限申请文案与最小化收集核查
- 敏感数据存储、传输与日志脱敏检查
- 内测渠道与问题收集机制

**完成标准**
- 无敏感信息硬编码，无密钥进入客户端包
- 日志不含完整敏感信息
- 实际收集的个人信息与隐私政策声明一致
- 内测反馈的阻塞级问题清零

**暂不处理**：大规模压测、多地域部署。

- 生产构建可在真机稳定运行
- 通过目标应用商店审核
- 具备可回滚的发布流程

**暂不处理**：增长投放、ASO 优化、多语言。
