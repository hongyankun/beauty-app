# 项目简介（Project Brief）

本文件定义产品是什么、为谁做、做什么、以及明确不做什么。
任何新增需求在动手前都应先与本文件核对；与本文件冲突时，先提出问题，不要自行扩大范围。

相关文档：[架构](./ARCHITECTURE.md) · [决策记录](./DECISIONS.md) · [路线图](./ROADMAP.md)

---

## 1. 产品定义

一款面向个人消费者的**轻医美项目记录、套餐资产管理和中立科普 App**。

它不是交易平台，不是社区，也不是诊断工具。它的本质是"用户自己的医美消费与知识档案"。

## 2. 核心用户

- 有轻医美消费习惯的个人用户
- 常购买多次卡、组合套餐
- 需要记录项目、机构、金额、余次和核销历史
- 医美实际发生频率不高，但长期关注项目、仪器、材料和护理知识

由此得出一个关键设计约束：**记录行为是低频的，知识消费是高频的**。产品不能只靠"记账"维持打开率，百科与收藏承担长期活跃的职责。

## 3. 核心价值

- 管理医美套餐和剩余次数
- 保存真实、连续的个人医美消费历史
- 降低遗忘、重复购买和套餐浪费
- 用百科、收藏和心愿单提高长期使用频率
- 提供基于记录的信息整理和一般性科普提示

## 4. MVP 核心模块

1. **首页** —— 概览与统计入口
2. **记录** —— 套餐、项目、核销历史
3. **医美百科** —— 中立科普内容
4. **心愿单与收藏** —— 未来想做的项目、收藏的知识
5. **我的** —— 账号与设置

## 5. 第一阶段核心业务闭环

```
新增套餐
  → 添加套餐项目
  → 查看套餐详情
  → 核销一次
  → 剩余次数更新
  → 首页统计更新
```

这条闭环是第一阶段唯一必须跑通的主线。在它完整可用之前，不应投入其他模块的功能开发。

## 6. 明确不做

以下均为**已排除项**，不是"以后再说"，而是当前版本的边界。若要重新讨论，需要新增一条 ADR。

- 不做前后照片对比
- 不调用相机或相册
- 不做医疗诊断
- 不让 AI 冒充医生
- 不承诺治疗效果
- 不做社区
- 不做机构评分
- 不做医美预约和交易
- 不做机构入驻
- 不做 B 端数据产品
- 不做广告推荐
- 不做多人共享账户
- 不做护肤品每日使用打卡
- 第一版不做复杂 AI 推荐

## 7. 产品边界（AI 能力红线）

**AI 只能：**

- 总结记录
- 提醒待核销项目
- 解释一般性项目知识和常见周期
- 生成用户面诊时可以询问医生的问题

**AI 不能：**

- 诊断皮肤疾病
- 确认用户适合某个项目
- 直接制定治疗方案
- 替代具备资质的医生

这条边界同时是合规底线。任何 AI 相关的文案、提示词和输出，都必须落在"记录助手 + 科普助手"的定位内，参见 [ADR-009](./DECISIONS.md#adr-009-ai-定位为记录与科普助手不是医生)。
